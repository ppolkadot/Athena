# Athena native glass spike implementation plan

> Phase S1 / A1 only. Run the steps in order and record the results. The user authorized implementation of this isolated experiment.

**Goal.** Decide whether one wallpaper-sampling glass panel is viable in Athena's existing native renderer. Leave a runnable demo and a results record that a later implementer can reproduce.

**Inputs.** [Claude's review and Phase S1](../../reviews/2026-11-17-opus-athena-appearance-analysis-and-prompt.md#phase-s1-disposable-glass-spike-now-depends-only-on-a-reference-device), [appearance roadmap](2026-11-17-athena-native-appearance.md#a1-prove-one-native-glass-panel) and [contracts](../specs/contracts.md). Baseline is bc9f18f with existing local recovery, packaging and planning edits. Preserve those edits. The stock lock resolves eframe/egui-wgpu 0.37.0 and wgpu 30.0.1. Use eframe's re-exports. The experiment neither opens an Athena data directory nor depends on 1.2, a new Cargo dependency, or future appearance decisions.

**Own only:** examples/glass_spike.rs, examples/shaders/wallpaper_glass.wgsl, and docs/design/athena-glass-spike.md. Small example-private modules under examples/glass_spike/ are fine if they keep rendering code readable. Use a standalone eframe app and generated pixels. Keep the shipping shell, migrations, media storage, app controls, release jobs, manifest/lockfile, and user data out of scope. Do not commit, push, or tag as part of this task.

## 1. Match the three control cases

- [ ] Write pure regression tests inside the example for Fill UV geometry of a 16:9 source in wide, tall and matching-aspect viewports. A centered crop must stay inside [0,1] and be symmetric. Confirm that a point inside the glass samples the wallpaper at the same global position whether the panel is centered or offset, at both 1× and 2× pixel scales. Test zero-size inputs and make the GPU path skip them. Test that a missing or failed resource state selects Solid and that software adapters default to fallback. Run the example tests with the implementation absent or stubbed and confirm the failing cases.
- [ ] Generate one deterministic bright/dark checker-gradient wallpaper in an egui texture, retain its handle, and draw it with a background-layer painter. Initial allocation comes first. Use partial updates only when changing a same-sized texture. Keep painting independent of input capture. Create one fixed-layout panel with the same title/body/edit field and focus affordance in all three modes. Use labels/buttons or documented keyboard shortcuts for Solid, Tint, Glass, forcing unavailability, and starting a finite benchmark. The mode, effective path and fallback reason must be visible. Keep typed input through mode changes and resize.

## 2. Build the callback and prove its sampling

- [ ] In the native example, instantiate a callback through eframe::egui_wgpu. Give egui and the callback identical source pixels and global crop math. Use the example's own source GPU texture if sampling an egui-managed texture is impractical. Prepare a horizontal then vertical blur in quarter-resolution targets with distinct input/output resources. Cache resources in CallbackResources. Key target allocation by backing-pixel extent/format and blur regeneration by source generation and affected dimensions. A stationary wallpaper at fixed size must not re-upload or re-blur solely because another egui widget repaints. Log counts of uploads, target creations and blur runs. On resize/DPI changes, keep resource bounds and alignment correct, and avoid GPU work on a zero-area surface.
- [ ] In the callback paint stage, draw just one rounded, clipped wallpaper sample. Use the actual target format and the corresponding egui output encoding/premultiplied blending convention. Check the gamma path for the normal non-sRGB target; branch or report unsupported formats rather than assuming. Match panel-local physical coordinates to the global wallpaper crop. Keep text and input outside the effect. Compare an offset panel over high-contrast checker boundaries, inspect corner/edge bleed, and test wide/tall layouts. Use scoped validation where the wgpu API supports it. An unavailable renderer/resource or software-adapter gate must produce a solid panel and a visible reason. The forced-failure switch exercises that same decision path and is not evidence of actual device-loss recovery.

## 3. Make the experiment measurable

- [ ] Provide a finite reproducible workload. Run the same 60 Hz repaint schedule for all three modes with at least 60 warmup frames and 300 recorded frames per mode. Measure actual frame intervals independently of CPU UI/callback submission work. Record GPU time only if supported and collected, or mark it unavailable. Use the same viewport, scene and workload in all modes. Report cold blur/resize separately from warm steady state. Stop synthetic repaints once the run ends and count outgoing example-owned repaint requests in a focused, stationary 5-second idle check. Use a documented method for process memory, or mark it unmeasured.
- [ ] Record adapter/backend/driver, OS, actual client pixels, native DPI, mode, sample count, p50/p95 frame interval, CPU timing definition, cache counters and limitations. Try 1920×1080 and 100/125/150/200% Windows scale where locally attainable. Report simulated scale separately from native DPI. Record unsupported dimensions, missing measurements, and any manual steps that couldn't run. A software or headless result can validate logic, but cannot establish reference-device performance. Compare against the existing 16.7 ms at 60 Hz target and disclose v-sync/timer precision, any scheduler jitter, and whether the result includes presentation. Leave glass disabled for production unless reference-device performance, readable text, fallback and idle behavior are all demonstrated.

## 4. Return evidence

- [ ] Run cargo fmt --check, cargo test --locked --example glass_spike, cargo clippy --locked --all-targets -- -D warnings, cargo test --locked and document lint. Build the release example and launch with cargo run --release --locked --example glass_spike if the desktop is available. Report exact results and observed regressions. Use Windows document lint from the docs/superpowers directory with CRLF normalization if required.
- [ ] In docs/design/athena-glass-spike.md describe how to run the demo and controls, then summarize observations and include a results table that distinguishes measured values from pending checks. Record the specific recommendation for glass as experimental, viable on the measured configuration, or keep Solid/Tint. Report files and tests back to Codex. A clean compile alone does not pass the visual or performance checkpoint.

## Notes for the follow-on plans

- Recovery and packaging findings from Claude already have working tree fixes. The release still needs interactive smoke and a hosted package run. This example can proceed independently.
- Use a verified backend capability/fallback and measurements to gate glass. wgpu state alone is expected in the existing build. Static wallpaper first allocates one texture and should reuse same-sized storage on updates. Bounded decoding, retention policies, format 4, and native accessibility signal changes remain ensuing tasks.
- Keep the 16 MiB input, 2048-axis, frame-count and retained RGBA bounds as separate ceilings. A decoded canvas and downscaler have their own peak budgets. Separate delay normalization from the presentation cap, and test absent/finite/infinite loop metadata against the actual decoder before freezing those rules.
- Format 3 needs explicit per-version dispatch and a frozen format-2 fixture before changing the write format. For 1.3, preserve local appearance on legacy import unless a product decision says otherwise, and treat malformed appearance data as an optional-load failure. Keep reduced motion and Windows preference changes separate from 60 Hz repaint scheduling. Decide how to suspend a focused poll without losing the ability to notice when accessibility settings change again.
