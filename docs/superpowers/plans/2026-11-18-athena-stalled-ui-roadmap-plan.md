**Handoff for Claude Sonnet 5.5 Medium.** Start on `main` at `3101d73` or its verified successor. Execute one task at a time in the order below. Each task names its owner, behavior and acceptance tests. Use the original plans for their detailed test lists and use this roadmap to resolve open choices and supersede stale instructions. The [contracts](../specs/contracts.md) and [definition of done](../../dod.md) govern the implementation.

## Review focus

- First Enter, repeat key and duplicate-dialog confirmation share one input frame boundary. Task 4 requires evidence the transition never writes twice.
- Stored even participants can differ from the active roster. Tasks 1 and 3 verify unchanged participants, remainder assignment and archived repair.
- Report and selection refresh can fail after a committed write. Tasks 5, A2 and G2 preserve coherent cached state and retain the existing committed outcome model.

- Historical closing references and amounts can diverge after Trash/purge or a comparison-month edit. Tasks G3–G5 verify stable saved values, stale markers and portable projection together.
