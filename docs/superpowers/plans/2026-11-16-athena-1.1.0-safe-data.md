# Athena 1.1.0 — Safe data

> **For agentic workers:** Execute tasks in order. Each task names its contract sections, owning files, non-goals, and the tests to write **before** implementation. Every task ends with the standard verification footer ([contracts §13](../specs/contracts.md#13-verification--frozen-for-11)) and a commit. Do not restate or change contracts inside a task; if a contract is wrong, edit [contracts.md](../specs/contracts.md) in the same commit and add a §15 line. Tagging and publishing are user actions.

**Goal:** Make Athena's data hard to lose and its shared-expense math trustworthy. This release covers trash with undo, manual backups, validated restore, versioned JSON import, and settlement with recorded paybacks.

**Prerequisite:** [Phase 0](2026-11-16-athena-phase-0-foundation.md) complete (v1.0.2 tagged, CI green, Settings split).

**Out of scope (later releases):** one-line entry, templates, duplicate warnings, day drill-down, insight, XLSX (1.2); design system, icons, wallpaper, glass, customization (1.3); goals and closings (1.4). Import merge mode is out of scope entirely.

**Tests first** (in `migrations.rs` / `db/mod.rs`):
- `fk_off_migration_restores_foreign_keys_on_success_and_failure`: a two-step list where step 2 carries the marker. Assert `foreign_keys` is 1 afterwards, on both a passing and a failing step.
- `fk_off_migration_rolls_back_on_foreign_key_violation`: a marked step that leaves a dangling allocation fails and leaves `user_version` unchanged.
- `upgrade_v1_preserves_rows_allocations_and_ids`: build a v1 file with `MIGRATIONS[..1]`, seed it with `seed_mixed`, then open with the full list. Counts, ids, allocations and `integrity::check` are all unchanged.
- `upgrade_v1_does_not_reuse_hard_deleted_ids`: on v1, insert three rows and hard-delete id 3. After the upgrade, a new insert gets id ≥ 4.
- `schema_accepts_settlement_and_guards_its_shape`: a settlement with payer and no category inserts. Without payer, or with a category or split mode, it is a CHECK failure.
- `trash_column_view_and_application_id_exist`: `deleted_at` is a column; `live_transactions` hides a row with `deleted_at` set; `application_id` = `0x41544E41`.
- `upgrade_writes_pre_migration_backup` (existing behavior, re-asserted for v1 → v3).

**Steps:**

- [ ] Implement marker detection and the §4.1 sequence in `run_migrations_with`. Restore the pragma with a guard so every path restores it.
