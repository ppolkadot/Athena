## Global Constraints

- All 1.0 and 1.1 constraints still apply.
- Bump `Cargo.toml` to `version = "1.2.0"`.
- Goal contributions are not expenses and do not change balance, income, or month result.
- Goal progress uses integer money. No float money.
- Owner name lives only in `people`. Goals store `person_id`; they never store a person's name.
- Category labels resolve through current rows. Closings store `top_category_id`, never a category name.
- Closing snapshots store numbers, not rendered sentences. Insight is rendered in the active language.
- Monthly closing stores a snapshot. Recomputing requires explicit confirmation.
- Every new visible string exists in English and pt-BR. No visible literals in `goals.rs`, `closing.rs`, or month/calendar closing widgets.
- Every export remains atomic: temp file, validate, rename. A failed export leaves the previous file intact.
- Archive replaces delete for goals. Hard delete is only for contributions, with confirmation.

## Review Focus

1. **Goal money vs expenses:** adding a contribution must not change the month summary, tracked balance, or category totals.
2. **Target date in the past:** contribution plan must not divide by zero or show a negative period count.
3. **Goal over-contribution:** progress can exceed 100%, remaining clamps at zero, percent display capped at 100% with a `complete` state.
4. **Closing on an empty month:** snapshot stores zeros, insight renders a calm empty sentence, no panic.
5. **Recompute safety:** re-closing a month replaces the snapshot only after confirmation and updates `closed_at`.
6. **Language switch after closing:** a closed month's insight, status labels, frequency labels, and buttons all render in the newly selected language without rewriting the snapshot.
7. **Rename after closing:** renaming the top category changes the closing card label. Renaming the owner changes goal attribution. No duplicated name columns.
8. **Archived references:** archiving a person or category keeps existing goals and closings readable, and removes them from new-entry pickers.
9. **Export completeness:** JSON carries goals, contributions, and closings with structured fields; XLSX adds `Goals` and `Closings` sheets with localized headers. Both stay atomic.
10. **Migration safety:** v3 migration rolls back on failure; a v4 database is refused with `SchemaTooNew`; upgrading a v1 or v2 file writes a pre-migration backup before the pending batch.

```sql
CREATE TABLE goals (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL CHECK (length(trim(name)) > 0),
    description TEXT,
    target_cents INTEGER NOT NULL CHECK (target_cents > 0),
    target_date TEXT CHECK (target_date IS NULL OR target_date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'),
    frequency TEXT NOT NULL DEFAULT 'monthly' CHECK (frequency IN ('daily', 'weekly', 'monthly')),
    person_id INTEGER REFERENCES people(id) ON DELETE RESTRICT,
    icon TEXT,
    status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'paused', 'completed', 'archived')),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE INDEX idx_goals_status ON goals(status);

CREATE TABLE goal_contributions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    goal_id INTEGER NOT NULL REFERENCES goals(id) ON DELETE CASCADE,
    amount_cents INTEGER NOT NULL CHECK (amount_cents > 0),
    date TEXT NOT NULL CHECK (date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'),
    note TEXT,
    created_at TEXT NOT NULL
);
CREATE INDEX idx_goal_contributions_goal_date ON goal_contributions(goal_id, date DESC, id DESC);

CREATE TABLE month_closings (
    month TEXT PRIMARY KEY CHECK (month GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]'),
    income_cents INTEGER NOT NULL,
    expenses_cents INTEGER NOT NULL,
    refunds_cents INTEGER NOT NULL,
    net_cents INTEGER NOT NULL,
    tx_count INTEGER NOT NULL CHECK (tx_count >= 0),
    top_category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    largest_expense_id INTEGER REFERENCES transactions(id) ON DELETE SET NULL,
    largest_expense_title TEXT,
    largest_expense_cents INTEGER,
    fingerprint TEXT NOT NULL,
    previous_net_cents INTEGER NOT NULL DEFAULT 0,
    previous_count INTEGER NOT NULL DEFAULT 0,
    closed_at TEXT NOT NULL
);
```

Schema notes: no person name, no category name, no insight string. `largest_expense_title` is a deliberate display fallback, not the canonical label: while the transaction row exists its current title is used, so renames stay live; the stored title reappears only after a purge. `goal_contributions` cascades on goal delete. `goals.person_id` is `RESTRICT` and `month_closings.top_category_id` is `SET NULL`. Archiving is the only in-app removal and never fires an FK action; `RESTRICT` blocks an accidental hard delete of a person still referenced by a goal, while `SET NULL` lets a defensive category cleanup leave the closing intact.

`Goal` holds `person_id: Option<i64>`, never a name. Basis points = `min(contributed * 10_000 / target, 10_000)` in `i128` intermediates to avoid overflow, then cast. ## Self-Review Notes

- Goals and contributions have no path into transactions or reports. Review Focus 1 pins it with a test.
- Past target dates and zero periods handled without division by zero. `checked_ceil_div` rejects divisor 0.
- Over-contribution capped for display, exact for money.

- Owner and category names resolve through current rows. No duplicated name columns.
- Archived goals, people, and categories keep history and leave pickers.
- JSON carries goals, contributions, and closings and still imports 1.1 documents; XLSX adds localized full-history sheets while monthly sheets obey `ExportScope`.
- Migration safety covers rollback, pre-migration backup (including v1 → v3 in one step), and newer-schema refusal.
