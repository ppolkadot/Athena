# Athena 1.0.2 contrast and foundation brief

**Status:** Version and scope confirmed by the user on 2026-11-13; ready for detailed task expansion.
**Base:** The published 1.0.1 foundation at `3b934e3`; do not move its tag.
**Decision register:** [Roadmap revision](2026-11-13-athena-roadmap-revision.md), D1 and D5.
**Historical context:** [1.0.1 reconciliation](2026-11-13-athena-1.0.1-revision-brief.md)

## Goal

Correct remaining contrast and foundation inconsistencies in a small patch. Preserve Semibold main text, Bold titles, frozen-tabular Semibold amounts/dates, and the category overflow fix already shipped in 1.0.1. The broader Apple/Onyx redesign and animations belong to 1.1.

## Scope and boundaries

In scope: semantic text contrast, palette regression coverage, precise font provenance/documentation, verification of long-label/amount layouts with the heavier type, refreshed affected snapshots, and versioned release checks.

Out of scope: new screens, navigation composition, new icon sets, materials, animation systems, persistent accessibility preferences, schema migrations, import/restore, and new financial features. Do not turn verification of an existing layout fix into a new general redesign.

## Work package 1 — Contrast by text role

**Owning files:** `src/ui/theme/palette.rs`, `src/ui/theme/mod.rs`, amount/control components if a token is shared incompatibly, and palette tests.

- Require at least 4.5:1 for ordinary-sized text against its actual surface. Include positive/negative amounts, accent text, warnings, selected controls, and primary-button labels.
- Check background, panel, card, hovered card, and composited selected states. Keep 3:1 only where the content genuinely qualifies as large text or a non-text indicator.
- Darken the existing light-theme hues rather than changing the visual identity. Candidate light text values measured during planning are accent `#3F55C6`, positive `#147D52`, negative `#B83247`, and warning `#7A5B00`. They exceed 4.5:1 against the existing white, page, and hovered-card surfaces; composited control states still need their own checks.
- Split text and decorative/chart tokens only if the existing shared token cannot satisfy both roles. Preserve semantic signs and labels.

**Acceptance:** a normal-text contrast regression fails on the 1.0.1 palette and passes with the correction. Tests cover every actual text/background combination, not only the three candidate surfaces. Visual review checks both themes and primary/selected/hover/focus states.

## Work package 2 — Reconcile the font contract

**Owning files:** `assets/fonts/PROVENANCE.md`, `tests/fonts.rs`, `src/ui/theme/typography.rs` if a factual correction is required, the main design spec, designer brief, and historical plan annotations.

- Document that the tabular derivative comes from Semibold. Preserve the already-correct explicit Bold family mapping.
- Record the upstream Bold metadata quirk and test selected-face identity. Metadata normalization, if performed, must be generated and documented reproducibly; it is not a substitute for selecting the actual Bold outlines.
- Preserve the upstream license bytes, source pin, author metadata, Latin coverage, and size constraints.
- Keep the canonical designer brief under 4,000 characters and synchronize its mirrored appendix if the brief changes. Do not expand it with the entire new roadmap.

**Acceptance:** documentation matches shipped/generated bytes, digit advances remain equal, all five committed assets remain covered, and the brief/appendix checks still pass.

## Work package 3 — Layout and final-artifact verification

**Owning files:** existing long-category regression test, transaction/rail components if it reveals a remaining failure, `src/ui/snapshot_tests.rs`, affected snapshots, and `docs/smoke-1.0.md`.

- Run the category/amount regression with both themes, Portuguese/English, long person/category/title values, and large supported amounts. Keep monetary values visible; truncated labels retain an accessible full-value route.
- Review 1100×760, the supported minimum window, and Windows scaling at 100%, 125%, 150%, and 200%.
- Refresh affected snapshots using embedded fonts and a controlled clock. Review changed images; do not raise comparison tolerance.
- Build the release executable and installer. Repeat native typography, accent/symbol, keyboard, restart, and installation/license checks against these exact new artifacts. Earlier smoke checks are historical and do not validate a new binary hash.

## Versioning and release deliverables

Set Cargo, lockfile, installer, and active README release text to 1.0.2. Add a dated 1.0.2 section to the smoke record with the actual tested executable and installer hashes. Keep the 1.0.1 notes and published tag intact.

The detailed implementation plan must include the failing contrast test, exact palette/control edits, documentation text, targeted regression commands, snapshot review, and the final build/install procedure. This brief defines those requirements but is not itself a command-by-command execution plan.

Required gates: `cargo fmt --check`; `cargo clippy --all-targets --locked -- -D warnings`; `cargo test --locked`; `cargo build --release --locked`; document lint; whitespace/link checks; and recorded native smoke results. Installation checks compare the installed executable/license bytes to build inputs and clean up only the isolated test installation.

The release handoff must distinguish clean-machine coverage from same-machine testing and identify the exact commit that produced the verified artifacts. Creating these documents does not authorize moving tags, publishing a release, or claiming unperformed checks.
