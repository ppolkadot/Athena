# Athena 1.0.1 foundation revision brief

**Status:** Confirmed historical reconciliation. Remaining corrections are assigned to 1.0.2.
**Baseline:** `3b934e3`, already present at remote `v1.0.1` on 2026-11-13.
**Original plan:** [2026-11-13-athena-1.0.1.md](../plans/2026-11-13-athena-1.0.1.md)

## Goal

Establish a consistent, legible type foundation and reliable dense layouts without changing financial rules, stored data, or the entry workflow. Record the work already shipped accurately, then assign remaining corrections to an approved follow-up release.

## Already implemented in the observed baseline

- Embedded Latin subsets, pinned source, upstream license, renamed derivative families, and reproducible asset generator.
- Semibold for main UI and controls; Bold for section, heading, and display styles.
- Frozen-tabular Semibold for amounts and dates; the generator now uses `TABULAR_SOURCE = "Semibold"`.
- A real embedded Bold asset; headings do not depend on `.strong()` to choose weight.
- Category truncation and full-name hover text in transaction rows and the category/person rail, with a regression test.
- Updated release executable and installer hashes in the smoke record.

These observations come from current source. Earlier native smoke observations predate the last rebuild and must be rechecked against the current artifact before claiming they verify that artifact.

## Corrections carried into 1.0.2

The user selected a new patch release. The [1.0.2 brief](2026-11-13-athena-1.0.2-revision-brief.md) owns the following work; it must not be added by moving the published 1.0.1 tag.

### 1. Reconcile the documentation with the actual font mapping

**Owning files:** `src/ui/theme/typography.rs`, `tools/fonts/build.py`, `assets/fonts/PROVENANCE.md`, `tests/fonts.rs`, `docs/superpowers/specs/2026-11-11-athena-design.md`, `docs/design/athena-designer-brief.md`, and the original 1.0.1 plan.

- Preserve the current Semibold-body/Bold-title mapping in the active design spec and reconcile any older mapping left in planning/provenance text.
- Document the Semibold origin of the tabular derivative explicitly in provenance.
- Review the retained Regular/Medium assets as fallbacks; do not remove them solely as part of a documentation correction.
- Preserve the upstream license bytes and required author metadata.
- The pinned upstream Bold face has distinct outlines but weight-class metadata of 600. Select it explicitly by family and test its actual identity. If derivative metadata is normalized to 700, document the modification and regenerate it reproducibly; never edit the original upstream license or font checkout in place.

**Acceptance:** font-family tests cover body, secondary, buttons, headings, and painter-based titles; tabular digit advances are equal; derivative identity and provenance match the generated bytes.

### 2. Correct normal-sized semantic-text contrast

**Owning files:** `src/ui/theme/palette.rs`, `src/ui/theme/mod.rs`, amount components, and palette tests.

- Use at least 4.5:1 for ordinary text, including 15-size register amounts, secondary colored copy, and text buttons. Use 3:1 only for qualifying large text or non-text indicators.
- Evaluate color on every actual surface and state, including tinted selected controls and primary-button text.
- Separate semantic text tokens from decorative/chart colors where one color cannot meet both roles.
- Preserve positive/negative labels and signs. Semibold does not substitute for adequate contrast.

**Acceptance:** tests check each text role against its real background; both themes pass without making text larger simply to relax the threshold. The light positive color's previously measured approximately 3.40:1 against white is not accepted for normal text.

### 3. Verify the heavier type and overflow fix together

**Owning files:** `src/ui/components/transaction_row.rs`, `src/ui/screens/month.rs`, `src/ui/quick_add.rs`, `src/ui/snapshot_tests.rs`, `src/ui/snapshots/`, and `docs/smoke-1.0.md`.

- Reserve the amount column before allocating title/category/name space.
- Preserve the full value through hover and an accessible detail or edit path; important financial values must remain visible without hovering.
- Verify English and Portuguese at 1100×760, the supported minimum window, and Windows scaling at 100%, 125%, 150%, and 200%.
- Test long category/person names, long titles, large supported amounts, and keyboard focus. If the amount itself exceeds the available width, use an explicit adaptive layout rather than overlapping adjacent content.
- Keep snapshot fonts independent of host fonts. Never increase pixel tolerance to conceal a regression.

**Acceptance:** every checked snapshot is reviewed; native Quick add and register checks use the newly built executable, with its hash recorded.
